# 第一阶段验收：Tracker 学习行为记录

本阶段验收代码编辑记录、正常服务会话结束记录和中文记录查看入口。学习工作台另见 [第二阶段验收说明](dashboard-acceptance.md)，历史复盘见 [第三阶段验收说明](history-acceptance.md)。

## 打开网页验收环境

1. 按 [README](../README.md#新电脑首次安装与启动) 安装并启动网站。建议使用独立验收数据目录，避免混入日常学习记录。
2. 浏览器打开服务地址，在侧栏进入“行为记录”。
3. 在课程页修改代码后返回“行为记录”，点击“刷新记录”读取最新元数据。

本阶段编辑记录验收无需 AI 密钥，也无需运行 Spark 作业。已有学习记录可以继续使用，无需清空数据库。

## 1. 综合题中的编辑能被记录

打开 Learning Spark 第 11 课“调试与新场景迁移练习”，进入订单调试代码题。在网页编辑器增加一行注释，如 `# tracker-check`，停顿一秒，然后查看学习行为记录。

- [ ] 出现“编辑代码”记录，归属 `11_diagnosis_practice:debug_orders`。
- [ ] 能看到修改次数、增加字符数和删除字符数；修改次数表示编辑变更数量，不是键盘按键数。
- [ ] 连续输入会聚合，停顿约一秒后发送，无需每敲一个字符都生成一条日志。
- [ ] 查看器只显示编辑计数，不显示注释正文或完整代码。

## 2. 自动准备代码和其他输入不算学生作答

打开其他课节的代码题，先不要输入代码，查看记录。随后在课程搜索框或导师问题框输入文字但不发送，再查看记录。

- [ ] 打开题目、填入起始代码和恢复已保存代码，不会生成学生“编辑代码”记录。
- [ ] 搜索框、模型配置框和导师问题框的输入，不会记成当前题的代码编辑。
- [ ] 短代码题和综合题都能记录当前题的用户编辑；记录以课程、课节和稳定题目标识绑定，不以浏览器文件名猜测题目。
- [ ] 查看参考答案不会生成学生编辑记录；答案查看行为单独记账。其他标签页的过期题目标识不能把编辑归到当前新题。

## 3. 快速切课不会把编辑归到新题

在当前代码题输入一行注释后，立即点击侧栏的另一课，随后查看记录。

- [ ] 待记录的编辑仍归属原课、原题，不会出现在新题名下。
- [ ] 改变课节或难度时，已发送及待发送编辑都保持原来的归属。
- [ ] 刷新恢复课节后，显示题目、保存草稿和后续编辑的归属保持一致。

## 4. 正常关闭服务能结束会话

在代码题中修改代码并等待保存，随后在启动终端按 Ctrl+C 正常停止服务。重新启动网站、刷新浏览器并查看行为记录。

- [ ] 能看到旧会话的“会话结束”和新会话的“会话开始”。
- [ ] 旧会话结束最多记录一次，已发送的编辑仍能读取。
- [ ] 已有学习进度和事件仍能读取。

浏览器刷新或关闭标签页不等于后端会话立即结束；服务会保留标签页状态以便恢复。会话结束表示正常服务关闭等生命周期事件已到达后端。强制结束进程、断电等情况可能缺失结束记录；不能据此推断学习者学习时长或能力。

## 5. 编辑行为不会凭空改变学习分数

先打开侧栏“学习画像”并记录四维分数和证据数量。仅编辑代码，不运行、不提交、不请求提示，再刷新画像。

- [ ] 事件数量可以增加，四维分数和评估样本数量保持原状。
- [ ] 运行、提交、提示和答案查看仍按原有诊断规则处理。

## 最近记录与失败处理

查看器展示最近 200 条记录，按页面标明的记录顺序显示；超出范围会说明还有更早记录，可在学习历史按题目查看。该显示范围不截断诊断使用的完整历史。读取失败时会显示提示，可以重新进入页面或点击刷新。

## 自动化验证

在已安装开发依赖的项目环境中，于仓库根目录执行：

```bash
python -m pytest tests/test_learning_events.py tests/test_tracker_protocol.py tests/test_diagnosis_integration.py tests/test_web_runtime_parity.py -q
```

浏览器行为检查（需要 Node.js）：

```bash
node --test tests/web_frontend.test.cjs
```

测试使用临时数据库和浏览器模拟，不会修改真实学习进度。后端还验证客户端只能提交允许的编辑元数据，不能伪造评估、提示或答案事件来改变画像。自动化检查之外，还需完成上面的真实浏览器操作。
