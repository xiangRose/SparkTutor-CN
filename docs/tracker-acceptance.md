# 第一阶段验收：Tracker 学习行为记录

本阶段补齐代码编辑记录、正常会话结束记录和中文记录查看入口。学习工作台及历史复盘属于后续阶段，待本阶段验收后再开发。

## 打开当前开发版

1. 在 VS Code 中打开 `sparktutor-vscode` 文件夹。
2. 确认 `sparktutor.pythonPath` 指向项目 `.venv` 的解释器。本机路径为 `D:\project\AI+KY\sparktutor\.venv\Scripts\python.exe`。
3. 按 F5；构建完成后，在新打开的“扩展开发宿主”窗口操作。
4. 按 Ctrl+Shift+P，执行“SparkTutor：查看学习行为记录”。后续每次执行此命令，都会重新读取最近的记录。

本阶段编辑记录验收无需 AI 密钥，也无需运行 Spark 作业。已有学习记录可以继续使用，无需清空数据库。

## 1. 综合题中的编辑能被记录

打开 Learning Spark 第 11 课“调试与新场景迁移练习”，进入订单调试代码题。在自动打开的订单综合题文件中增加一行注释，如 `# tracker-check`，停顿一秒，然后查看学习行为记录。

- [ ] 出现“编辑代码”记录，归属 `11_diagnosis_practice:debug_orders`。
- [ ] 能看到修改次数、增加字符数和删除字符数；修改次数表示编辑变更数量，不是键盘按键数。
- [ ] 连续输入会聚合，停顿约 500 毫秒后记录，无需每敲一个字符都生成一条日志。
- [ ] 查看器只显示编辑计数，不显示注释正文或完整代码。

## 2. 自动准备代码和其他文件不算学生作答

打开其他课节的代码题，先不要输入代码，查看记录。随后在未命名文件中输入文字，再查看记录。

- [ ] 打开题目、填入起始代码和恢复已保存代码，不会生成学生“编辑代码”记录。
- [ ] 编辑未命名文件、其他题的文件或参考答案文件，不会记到当前题。
- [ ] 短代码题的 `exercise.py` 和综合题的 `script_*.py` 都能记录当前题的用户编辑；文件名不作为后端题目标识。
- [ ] 短题共用文件时，只统计当前练习标记后的代码块；修改旧题块不计入当前题。删除或改变分块标记导致边界无法确认时，暂停该短题的编辑采集。

## 3. 快速切课不会把编辑归到新题

在当前代码题输入一行注释后，立即点击侧栏的另一课，随后查看记录。

- [ ] 待记录的编辑仍归属原课、原题，不会出现在新题名下。
- [ ] 在加载前取消难度选择时，原题仍能继续记录编辑。
- [ ] 关闭“恢复进度”提示时，会按提示说明继续已选课节，显示的题目与记录归属保持一致。

## 4. 正常重载能关闭会话

在扩展开发宿主中修改当前代码题，然后运行“Developer: Reload Window”（开发人员：重新加载窗口）。重新启用扩展后查看学习行为记录。

- [ ] 能看到旧会话的“会话结束”和新会话的“会话开始”。
- [ ] 旧会话结束最多记录一次，重载前的待记录编辑已提交。
- [ ] 已有学习进度和事件仍能读取。

会话结束表示正常关闭通知已到达后端。强制结束进程、断电等情况可能缺失结束记录；不能据此推断学习者学习时长或能力。

## 5. 编辑行为不会凭空改变学习分数

先打开“SparkTutor：查看学习诊断”并记录四维分数和证据数量。仅编辑代码，不运行、不提交、不请求提示，再刷新诊断。

- [ ] 事件数量可以增加，四维分数和评估样本数量保持原状。
- [ ] 运行、提交、提示和答案查看仍按原有诊断规则处理。

## 最近记录与失败处理

查看器展示最近 200 条记录，按时间先后排列；超出范围会说明还有更早记录。该显示范围不截断诊断使用的完整历史。读取失败时会显示提示，可以点击“重试”或重新执行命令。


```powershell

npm.cmd test
npm.cmd run build
```

测试使用临时数据库和模拟编辑器，不会修改真实学习进度。后端还验证客户端只能提交编辑和正常退出元数据，不能伪造评估、提示或答案事件来改变画像。
