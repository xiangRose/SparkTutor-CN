# AI 调试教练：配置与阶段验收

本阶段实现学习证据驱动的 AI 调试教练，先开放两道作者维护的练习：Learning Spark 首课的 M&M 综合题（`01_getting_started:15`）和调试诊断课的传感器迁移题（`11_diagnosis_practice:sensor_transfer`）。其他题目暂不开放。完成本阶段验收后，再决定是否扩展题库和开展真实模型对比实验。

## 1. AI 的职责与证据边界

请求包含当前题目、当前代码、有限的最新运行/反馈信息、已有四维指标及可引用的历史证据。模型选择作者维护的错误假设、引用实际存在的证据，并可生成有范围限制的小样例数字。模型只返回结构化数据，系统校验后显示对应的中文教学节点。**卡片的中文指导正文由作者维护，不是模型自由生成的答案。**

提示依次为概念追问、检查方法、局部示例；当前级别真正展示并确认后才可进入下一级。检查方法和可选反思用来引导“提出假设 → 检查 → 修改 → 再验证”，不能代替学生完成课程作业。没有证据时可以提出待检验假设，不能声称已经确定根因或推断能力不足。

小样例针对“记录条数与数量总和”的区别：模型提供 2–5 个 0–100 的整数，系统拒绝布尔值、越界值和总和恰好等于条数的无效反例。Python 固定参考模板计算条数与数量总和；不执行模型代码、学生代码或 Spark，不判断学生实现正确，不增加知识、调试修复或迁移成绩。

设计承接[学习诊断设计说明](learning-diagnosis-model.md)中的调试过程研究 R1、提示与反思研究 R5、低风险可追溯支持研究 R6。三层提示与假设目录是本项目的工程设计，论文没有验证本项目的分层阈值、模型质量或教学效果。完整的病例与后续实验方案见[教练评估说明](coach-evaluation.md)。

## 2. 填写自定义模型接口

1. 构建扩展后，用 VS Code 打开 `sparktutor-vscode` 文件夹，按 F5 启动扩展开发窗口。
2. 在该窗口的命令面板运行“SparkTutor：配置 AI 调试教练模型”，选择“填写 API 地址和模型名称”。填写服务商提供的基础地址（不包含 `/chat/completions`）及准确模型 ID，保存至个人设置；此时不会发出请求。
3. 地址与模型复用 `sparktutor.openaiBaseUrl`、`sparktutor.openaiModel`；请求使用兼容的 Chat Completions 接口。这里的“OpenAI 兼容”指协议格式，可以填写支持该格式的其他模型服务。
4. 再运行一次配置命令，选择“安全保存 API 密钥”，通过密码输入保存至 VS Code SecretStorage。不要把真实密钥写入示例、受版本控制的工作区设置或提交记录。仍兼容 `SPARKTUTOR_OPENAI_API_KEY` / `OPENAI_API_KEY` 环境变量及原有 `sparktutor.openaiApiKey`；密钥存储中的值优先。
5. 打开“SparkTutor：打开 AI 调试教练”。教练固定使用这套自定义兼容接口，不随原聊天功能自动回退到其他供应商。地址和模型必须明确填写，仅有扩展默认值不算配置完成；原聊天与评审的 `sparktutor.aiProvider` 仍独立生效。

需由服务商确认地址、模型 ID 和结构化指令兼容性；本阶段未代替用户填写凭据、付费调用或验证每家服务。模型请求会把上述当前代码和学习上下文发送到填写的服务。Tracker 数据库不记录提示正文、完整模型回复或代码原文。

## 3. 验收步骤

建议先使用独立 VS Code 配置/测试数据，避免将验收中的主动求助混入日常学习记录。仅打开或刷新面板不会调用模型或增加提示记录。

1. **未配置状态**：打开教练并尝试请求，确认页面指向配置入口，没有虚构的 AI 回答，也没有新增有效提示记录。
2. **进入练习**：从教练入口打开 M&M 练习。确认出现原始题面和起始代码；单题练习不覆盖顺序学习进度。从此入口进入传感器题不代表迁移前置条件已满足。
3. **第一次指导**：在代码中保留一个聚合逻辑问题，点击第一级提示。确认回复显示所选假设、需要检查的问题、引用证据和局限说明；无证据时应明确说明。
4. **提示记账**：回复展示后查看学习行为记录，出现一次 `hint_request`，类型为 `ai_coach`。重复确认同一条消息不会重复记账。失败、未展示或已失效的回复不记为已用帮助。
5. **逐级提示**：逐级查看第二、三级；不能直接跳到未解锁级别。中文节点应引导检查，不应提供整道题的完整实现。
6. **核验小样例**：若模型提供了有效数字，点击核验。确认页面明确标注 Python 参考计算，展示数量总和与记录条数；历史新增 `coach_probe`，画像的 K/D/T 没有因此增加合格成绩。
7. **时效性**：请求过程中编辑代码或切到其他题，旧回复不能覆盖当前页面。再切回同一道题，旧请求仍应失效。显示后重新运行、提交或查看答案，应使旧卡片失效或要求重新请求。
8. **答案影响与成绩**：正式成绩仍通过课程原有运行/提交链产生。看过参考答案后，教练要标记答案影响；新的请求和小样例不能恢复同题的独立评分资格。传感器首次失败后重试也不能变成新的首次迁移样本。
9. **故障**：填写无效地址或模拟不符合结构的回复，应得到错误提示；不显示原始模型正文，不伪造指导，不把错误计为学生失败。

## 4. 自动检查与实际模型验收的区别

后端测试覆盖结构校验、证据引用、代码与题目时效、提示确认及小样例不增成绩；扩展测试用模拟接口验证路由、配置、页面交互和过期响应。这些检查证明实现路径与规则，不证明真实模型的错误诊断准确率、回答质量或学习收益。

用户填好接口后，按上述步骤做真实模型验收，再使用评估病例固定模型与参数开展配对测试。完整保留失败和不确定结果；不能只挑选成功截图，也不能把合成轨迹算作真实学生实验。
