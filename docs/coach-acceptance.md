# AI 调试教练：配置与阶段验收

本阶段实现学习证据驱动的 AI 调试教练，先开放两道作者维护的练习：Learning Spark 首课的 M&M 综合题（`01_getting_started:15`）和调试诊断课的传感器迁移题（`11_diagnosis_practice:sensor_transfer`）。其他题目暂不开放。完成本阶段验收后，再决定是否扩展题库和开展真实模型对比实验。

界面验收时，在课程页右侧切换到“调试教练”；当前题不支持时，可从练习选项进入支持的题目。教练首先说明用途与操作步骤；支持的题目中，“概念提问 → 检查方法 → 局部示例”按钮应位于历史画像之前。课程历史画像、提示依据和工作原理默认折叠，展开后仍能核查原始说明。返回“学习工作台”只进行导航，不请求模型、不登记提示；教练提出的方向还需修改代码并提交判题验证。首次进入与返回导航见[学习首页验收](dashboard-acceptance.md)。

## 1. AI 的职责与证据边界

请求包含当前题目、当前代码、有限的最新运行/反馈信息、已有四维指标及可引用的历史证据。模型选择作者维护的错误假设、引用实际存在的证据，并可生成有范围限制的小样例数字。模型只返回结构化数据，系统校验后显示对应的中文教学节点。**卡片的中文指导正文由作者维护，不是模型自由生成的答案。**

提示依次为概念追问、检查方法、局部示例；当前级别真正展示并确认后才可进入下一级。检查方法和可选反思用来引导“提出假设 → 检查 → 修改 → 再验证”，不能代替学生完成课程作业。没有证据时可以提出待检验假设，不能声称已经确定根因或推断能力不足。

小样例针对“记录条数与数量总和”的区别：模型提供 2–5 个 0–100 的整数，系统拒绝布尔值、越界值和总和恰好等于条数的无效反例。Python 固定参考模板计算条数与数量总和；不执行模型代码、学生代码或 Spark，不判断学生实现正确，不增加知识、调试修复或迁移成绩。

设计承接[学习诊断设计说明](learning-diagnosis-model.md)中的调试过程研究 R1、提示与反思研究 R5、低风险可追溯支持研究 R6。三层提示与假设目录是本项目的工程设计，论文没有验证本项目的分层阈值、模型质量或教学效果。完整的病例与后续实验方案见[教练评估说明](coach-evaluation.md)。

## 2. 填写自定义模型接口

1. 按 [README](../README.md#新电脑首次安装与启动) 启动网站，打开侧栏“环境与 AI 设置”。
2. 在“兼容接口 / 调试教练”填写服务商提供的 API 基础地址、准确模型 ID、密钥和必要的额外请求头。基础地址按服务商要求填写，不包含最终 `/chat/completions` 路由。
3. 点击“保存设置”。请求使用兼容的 Chat Completions 接口；这里的“OpenAI 兼容”指协议格式，可以使用支持该格式的其他模型服务。保存不会自动调用模型。
4. 默认配置保留在本标签页的服务内存。可选择记住本机；Windows 使用当前服务账户的 DPAPI 加密密钥及额外请求头，其他系统没有安全存储时不回退为明文密钥文件。也可在服务启动前设置 `SPARKTUTOR_OPENAI_BASE_URL`、`SPARKTUTOR_OPENAI_MODEL` 和 `SPARKTUTOR_OPENAI_API_KEY` / `OPENAI_API_KEY`。
5. 点击“检查教练连接”，确认接口状态；此操作仅发送短测试消息，不发送题面和代码，也不计为学习提示。然后返回课程，切换“调试教练”并请求第一级帮助。

教练固定使用兼容接口，不随导师提供方选择回退到 Anthropic。导师问答与代码评审的提供方在上方独立选择，两种连接检查分别进行。连接正文成功也不能代替真实教练结构化回复及教学质量验收。

需由服务商确认地址、模型 ID 和结构化指令兼容性；本阶段未代替用户填写凭据、付费调用或验证每家服务。模型请求会把上述当前代码和学习上下文发送到填写的服务。Tracker 数据库不记录提示正文、完整模型回复或代码原文。

## 3. 验收步骤

建议先使用独立网页服务的数据目录，避免将验收中的主动求助混入日常学习记录。仅打开或刷新页面不会调用模型或增加提示记录。执行方式也要保存，但 Spark 运行与模型配置彼此独立。

1. **未配置状态**：打开教练并尝试请求，确认页面指向配置入口，没有虚构的 AI 回答，也没有新增有效提示记录。
2. **进入练习**：从教练入口打开 M&M 练习。确认出现原始题面和起始代码；单题练习不覆盖顺序学习进度。从此入口进入传感器题不代表迁移前置条件已满足。
3. **第一次指导**：在代码中保留一个聚合逻辑问题，点击第一级提示。确认回复显示所选假设、需要检查的问题、引用证据和局限说明；无证据时应明确说明。
4. **提示记账**：回复展示后查看学习行为记录，出现一次 `hint_request`，类型为 `ai_coach`。重复确认同一条消息不会重复记账。失败、未展示或已失效的回复不记为已用帮助。
5. **逐级提示**：逐级查看第二、三级；不能直接跳到未解锁级别。中文节点应引导检查，不应提供整道题的完整实现。
6. **核验小样例**：若模型提供了有效数字，点击核验。确认页面明确标注 Python 参考计算，展示数量总和与记录条数；历史新增 `coach_probe`，画像的 K/D/T 没有因此增加合格成绩。
7. **时效性**：请求过程中编辑代码或切到其他题，旧回复不能覆盖当前页面。再切回同一道题，旧请求仍应失效。显示后重新运行、提交或查看答案，应使旧卡片失效或要求重新请求。
8. **答案影响与成绩**：正式成绩仍通过课程原有运行/提交链产生。看过参考答案后，教练要标记答案影响；新的请求和小样例不能恢复同题的独立评分资格。传感器首次失败后重试也不能变成新的首次迁移样本。
9. **故障**：填写无效地址或模拟不符合结构的回复，应得到错误提示；不显示原始模型正文，不伪造指导，不把错误计为学生失败。

## 4. 自动检查与实际模型验收的区别

后端测试覆盖结构校验、证据引用、代码与题目时效、提示确认及小样例不增成绩；网页测试用模拟接口验证路由、配置、页面交互和过期响应。这些检查证明实现路径与规则，不证明真实模型的错误诊断准确率、回答质量或学习收益。

用户填好接口后，按上述步骤做真实模型验收，再使用评估病例固定模型与参数开展配对测试。完整保留失败和不确定结果；不能只挑选成功截图，也不能把合成轨迹算作真实学生实验。

在已安装开发依赖的项目环境中，于仓库根目录运行：

```bash
python -m pytest tests/test_learning_coach.py tests/test_coach_protocol.py tests/test_web_ai.py tests/test_web_runtime_parity.py -q
node --test tests/web_frontend.test.cjs
```

自动化使用临时数据和模拟模型。历史扩展阶段的测试数量及构建记录见归档文档；当前网页版本的分轮结果见 [CHANGELOG](../CHANGELOG.md)。真实模型联网验收和配对教学实验需单独报告。

## 5. 实际试用问题与重测（2026-10-18）

真实试用中出现了提交 120 秒超时、模型有时未通过结构校验的两个独立问题。日志中的 `ackCoachMessage` 表明已有提示成功展示；“执行超时”不表示接口未连接，也不能证明代码算法错误。四维摘要汇总当前课程的历史任务，例如 4/4 通过不代表当前 M&M 题通过；提交超时不新增可信成绩。

已发现并修复模型提示与校验规则不一致：已识别的环境故障、仅语法检查或 AI 评审故障下，只允许 `uncertain` 且 `probe` 必须为 `null`，现在会明确发送本次约束和使用真实证据 ID 的格式示例。模型返回完整单一 JSON 代码围栏时可以正常解析；多余正文、未知字段、虚构引用及不合规探针仍会拒绝。失败显示固定中文原因和安全错误码，不输出模型原文，不自动增加模型请求次数。

提交时现在实时显示 Spark 输出；超时、环境故障、可确认的作答错误分别给出反馈。超时不会再统一要求学生修改算法。执行上限保持 120 秒，不用延长等待或模拟运行替代真实课程结果。

本机独立检查使用 Python 3.12.3、PySpark 4.1.1、Java 17.0.12 及默认执行器：M&M 官方参考实现约 14.2 秒通过原课程断言，作者构造的计数代替求和样例约 12.2 秒得到预期断言失败，均未超时。本次没有复现原 120 秒超时，不能将版本检查或单次通过解释为已经确定或根治其原因；没有读取用户作业或调用用户模型。

网页重测时停止旧服务，启动更新后的后端并刷新浏览器。打开同一道 M&M 练习，保留测试代码，提交一次并观察实时输出；若完成断言失败，再请求教练概念提示。若再次超时，保留本次启动到超时的必要输出用于定位；教练显示环境提醒仍符合当前证据。模型校验若再失败，记录页面的固定错误码，例如 `COACH_RESPONSE_FORMAT`、`COACH_RESPONSE_REFERENCES` 或 `COACH_RESPONSE_PROBE`，不需要分享密钥或完整模型返回。

上述计时属于 2026-10-18 的历史环境样例，不能证明当前每台电脑或每次请求都能成功。真实模型需要在实际服务中重试验证；分轮回归结果见 CHANGELOG。

## 6. 网站更新后无法连接或仍显示旧状态

先确认启动终端中的服务地址、端口和实际 Python。后端文件更新后需停止旧服务并重新启动，再刷新网页；服务重启会更新连接令牌，旧页面可能要求刷新。不要同时启动两个实例争用同一端口或数据目录。

在环境页核对实际解释器，选择执行方式后点击“保存设置”，以“当前已保存的执行方式”和运行结果为准。选择“本机 Spark”不会自动安装依赖或替换解释器；需要其他环境时使用 README 的 `-PythonPath` 启动方式。

原扩展窗口启动后立即关闭、诊断启动配置和 IntelliCode 通知等问题，仅适用于 [vscode-legacy 扩展版本](https://github.com/xiangRose/SparkTutor-CN/blob/vscode-legacy/docs/coach-acceptance.md)，不属于网页启动流程。

## 7. 模型连接检查显示空回复

连接检查区分有正文、接口有响应但正文尚未验证、确实失败。空正文、仅思考或截断输出不会记为可用的教学回答；仅凭这些结果不能判断密钥一定错误。

保存配置后，可在“环境与 AI 设置”分别手动检查导师和教练连接。手动检查允许重试之前失败的配置；教练始终核对兼容接口，导师使用自己选择的提供方。界面区分认证、限流、超时、空正文和格式问题，不回显服务商原始错误正文。

连接有正文仍不能代替结构化教练验收。真实教练若没有有效正文会明确失败，不把推理内容当作教学回答，不伪造提示或追加求助记录。服务商特定参数及模型 ID 应按当前服务配置确认；历史扩展的 DeepSeek 试用过程保留在归档文档中，不作为当前网页版本已经验证该服务的证明。
