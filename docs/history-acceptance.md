# 第三阶段验收：学习历史与复盘

本阶段把题目历史、行为时间线、四维趋势和单次记录复盘接入 VS Code。评分沿用 Issue #5；指标变化描述平台可见记录，不直接证明能力提升或教学效果。

## 打开开发版

1. 在 VS Code 中打开本项目的 `sparktutor-vscode` 文件夹，确认 `sparktutor.pythonPath` 指向项目虚拟环境。
2. 按 F5，在新开的“扩展开发宿主”中操作。若之前的开发宿主仍开着，先关闭旧窗口，再启动本次版本。
3. 按 Ctrl+Shift+P，运行“SparkTutor：查看学习历史与复盘”，或从学习工作台的“历史与复盘”入口进入。

已有学习记录会继续使用，不需要清空数据库。基本验收可使用选择题，无需 AI 密钥、Java 或 Spark；综合题仍需要其声明的执行环境。页面不会填充虚构的演示历史。

## 1. 按题目回看自己的尝试

打开一课，进入任一选择题，先提交一次错误选项，再提交正确选项；打开历史面板并刷新。

- [ ] 同一道题聚合为一条题目历史，可看课程、课节、题目标题及提交次数。
- [ ] 最近提交结果和可用于诊断的评估资格有明确区分，不能把未经验证的 AI 评审、dry-run 或答案后的通过伪装成新的独立证据。
- [ ] 提示、答案查看、运行和编辑分别计数；阅读步骤与会话记录不混成已评估题目。
- [ ] 只有打开题目、没有评估时显示尚无有效评估，与真正提交失败有区别。
- [ ] 题目多时可以翻页；没有更多记录时按钮不可继续。分页不会截断诊断使用的历史。

旧版记录仍能查看，但缺少评估资格信息的结果不会被追溯认定为可靠成绩。课程或题目已经移出目录时，保留其历史标识与说明，不提供未经核验的重做入口。

## 2. 查看一次学习过程的时间线

在题目列表选择一题，查看它的事件时间线。

- [ ] 按记录顺序查看运行、提交、提示、答案查看和编辑等事件，并显示本机时区的时间。
- [ ] 运行成功与提交评估通过有区别；仅语法检查不会显示为完成了需要真实执行的题。
- [ ] 环境故障、AI 评审、旧日志和受答案影响的结果有解释，不混入独立掌握证据。
- [ ] 编辑只显示次数和字符计数；不展示代码原文、文件路径、聊天正文或原始错误堆栈。
- [ ] 事件很多时可以翻页。选择另一道题后，旧题的迟到结果不会覆盖当前题。

时间戳表示平台记录时间，不证明持续学习时长；编辑计数也不等于键盘按键数。无法观测的平台外帮助不被标成完全独立学习。

## 3. 核查四维变化的原因

在同题的有效提交记录中，先查看第一次错误提交的复盘，再查看后续正确提交的复盘。

- [ ] 每个维度显示该记录之前与之后的比例、样本数及分子分母。
- [ ] 无证据显示“证据不足”；第一条证据出现时说明新增证据，不把 `null` 当成 0 来计算涨幅。
- [ ] 数值差使用百分点，同时解释样本变化；Hint Dependency 是求助方式描述，不贴能力高低标签。
- [ ] 同题的重试只更新 K 的最近有效结果，不新增一个 K 任务样本；T 的首次结果不会被重交改写。
- [ ] 在后来再次提交失败后，回看更早的正确提交，其当时指标不会被后来记录倒灌。

前后比较使用所选事件之前的完整历史前缀，不只使用当前题或当前页面。因而可以保留来源课程、首次提示与答案影响等上下文。新情境迁移仍要求作者标注的来源任务先通过；复盘不会自动制造新的迁移样本。

## 4. 课程、时间范围与趋势

切换课程与全部历史、近 7 天、近 30 天，并查看四维趋势。

- [ ] 列表与趋势显示所选范围内的记录；旧来源证据仍能参与历史重建。
- [ ] 趋势只提供有限数量的真实证据记录点，标明展示范围，不伪装成完整历史曲线。
- [ ] 空维度不补为 0；各维度显示自己的样本数量，提示指标单独描述。
- [ ] 可以从趋势点进入对应记录复盘，确认数值来源。
- [ ] 快速切换范围时只显示最后一次选择的结果，页码重置，不沿用上个范围的过期目标。

这些趋势按当前规则和课程标注重建，并非过去实时保存的能力快照。题目组成、难度、样本量、答案查看、日志缺失或课程改版，都可能改变结果。不能用曲线升降直接证明能力升降，更不能把时间关联说成因果效果。

## 5. 刷新与其他模块

- [ ] 没有待记录编辑时，刷新与复盘只读取数据，不新增评估、不推进课节、不修改代码。
- [ ] 待记录编辑会在读取前补发元数据，不因此增加成绩。
- [ ] 原来的行为记录输出窗口、学习工作台、诊断与推荐仍可使用。
- [ ] 读取失败时有明确提示和重试入口；关闭页面后，迟到响应不会重新打开或改写界面。
