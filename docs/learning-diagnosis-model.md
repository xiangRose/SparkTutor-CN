# 学习诊断模型：研究依据、操作定义与验证边界

本文对应 `formative-evidence-v1`。本模块把课程评估和学习事件整理为可核验的形成性反馈，帮助学习者选择下一道练习。它不估计经心理测量标定的潜在能力，不用于排名、考试定级或成绩认证。

设计依据来自文末列出的 8 篇本地论文。论文支持关注知识表现、调试过程、情境化求助和迁移任务；**它们没有提出或验证本项目的四个比率公式**。以下公式、计数单位、排除条件和推荐规则均是本项目的工程操作定义，不能称为“论文中的四维能力模型”。

## 1. 为什么使用透明计数

当前项目没有足够的训练集、标准化题库、重复测量样本或外部效标。因此不训练知识追踪网络，不把少量提交映射成精确的“掌握概率”，也不组合一个加权总分。每个指标同时返回分子、分母及缺失原因；分母为零时返回 `null`，前端显示“暂无足够证据”，不能显示为 0 分。

知识追踪论文中的预测概率来自模型训练。DKT 用历史练习及答题结果更新循环网络，以交叉熵学习下一次答题正确性的预测参数 [R2，PDF 第 3–6 页]。PDKT 进一步引入知识点与程序代码表示，同样需要训练和留出数据评估 [R3，第 3、5–6 页]。本项目当前不具备这些条件，其通过率不等于 DKT 的隐状态或下一题正确概率。

在线行为与认知过程也不是一一对应关系：同一种点击可能对应不同的自我调节活动，需要结合任务、内容和时间顺序解释 [R8，第 11–13 页]。因此，“请求提示”“一次运行很快”“修改很多次”本身均不能直接证明能力强弱。

## 2. 证据单元与有效评估

任务通过 `(courseId, lessonId, taskId)` 区分，练习目录提供稳定 `stepId`、知识点、业务场景、先修任务及迁移来源。任务重复提交不会被当作多个知识样本。事件按时间稳定排序，同一时间戳保留原输入顺序，不用随机生成的事件 ID 推断先后。重复事件去重，具有相同 ID 而内容冲突的事件排除，异常时间戳计入数据质量信息。

时间精度不足时采用保守解释：提示或答案查看与评估具有相同时间戳，也视为该帮助已发生，不能据此声称无帮助作答。迁移来源的合格通过时间必须**严格早于**目标首次评估；同一时间戳不能证明来源已经先行通过。其他任务在目标评估以前或同一时刻已有相同场景评估时，也不把目标算作未见过的新场景。

有效评估要求：

- 事件是可评估题型的提交，具有明确布尔通过结果，并标记为可用于评估。
- 评估来源是选择题判定、明确答案判定、课程可信测试或题目约束的结构检查。结构检查的解释范围仅为其实际检查的要求，不能泛化为任意 Spark 语义正确。
- `RequiresExecution` 脚本必须经过真实执行及课程可信测试；学生修改自己的测试代码不能替代课程保留的测试。
- 本地模拟模式、基础设施故障、AI 服务失败等不产生知识或迁移的通过/失败证据。仅通过语法检查也不证明程序任务完成。
- 可确认的学习者代码语法错误可以开启调试失败过程；但随后“语法正确”不能结束该过程，仍需有效评估确认通过。

记录答案查看和提示请求的时间。只有实际提供的提示/答案才算相应事件。答案查看以前的有效表现保留；答案查看以后的同一任务评估仍可用于学习进度，但不能新增知识或迁移证据，也不能证明独立调试修复。该保守规则不声称学习者查看答案后不能学会，而是承认系统无法在同题中区分理解与复现，需要新的独立任务来检验。

“独立”在本文仅表示相关时点以前未记录内置提示使用或参考答案查看，**不证明学习者没有通过平台聊天、外部资料、同伴或外部 AI 获得帮助**。当前不分析聊天内容，也不把每次聊天都判定为求助。事件数据无法覆盖的帮助不能猜测为零。

## 3. K：最近任务表现

令 \(Q_K\) 为至少有一次未受答案查看影响的有效评估的唯一任务集合，\(last(q)\) 为该任务最近一次这样的评估，\(pass\) 为通过指示值：

\[
K = 100\times\frac{\sum_{q\in Q_K}pass(last(q))}{|Q_K|}.
\]

分母为空时 `K = null`。该百分比回答“已观察任务中，最近一次有效评估有多少通过”，不回答“学习者掌握了课程百分之多少”。题目覆盖、难度和机会不同，跨学习者的比率不能直接比较。

合理使用提示不扣分。另列首次有效评估通过率、最近评估前未记录内置提示或答案查看的任务数及通过率、提示辅助任务数、答案支持任务数。知识点统计把一道题的最近结果关联到作者标注的知识点，但多知识点题失败不能识别具体哪个知识点有问题。

例：任务 A 首次失败、提示后通过，任务 B 首次通过，任务 C 仅看过答案且随后通过。知识证据为 A、B 两题，`K = 2/2 = 100%`，首次通过率为 `1/2 = 50%`；C 不新增知识证据。这个结果不能描述成“三个知识点全部掌握”。

研究依据是顺序性的任务表现与知识点信息具有分析价值 [R2，第 3–5 页；R3，第 3、5 页]。取“最近一次”、任务去重以及等权计数是工程选择，尚无这些论文对其测量效度的验证。

## 4. D：经评估确认的调试修复

调试分析仅面向代码题。首次可归因于学习者的失败开启一个过程，后续连续失败属于同一过程；有效评估通过时过程结束。之后再次失败可开启新过程。基础设施异常不打开失败过程；答案查看会使进行中的过程从能力证据中排除，另列排除数量。

令 \(E_D\) 为已确认修复或截至观察时仍未修复的合格失败过程，\(R_D\) 为其中后来由有效评估确认通过的过程：

\[
D = 100\times\frac{|R_D|}{|E_D|}.
\]

没有失败过程时 `D = null`，不能因为“一直没有出错”而给调试满分或零分。提示辅助修复计为修复，同时分别显示有提示/无已记录提示的修复数量。未结束过程显示“尚未确认修复”；它可能只是学习者暂时离开，不能断言不会调试。因此该比率描述当前观察窗口，受观察时点影响。

课程调试题引导“比较预期与实际 → 提出假设 → 选择检查 → 修改 → 再验证”。这借鉴了 Klahr 与 Carver 对程序评价、错误识别、表示、定位和修正的过程分析 [R1，第 5–9 页]。论文还指出最终成功可能来自盲目尝试，单看成功不足以测量策略质量 [R1，第 19 页]。所以本项目 **D 仅衡量经验证的修复结果，不衡量定位效率、假设质量或调试策略深度**。当前不按修改次数、停留时间或一次运行成功发额外分数。

VS Code 调试数据采集论文支持过程事件、代码快照及分析工具的工程可行性 [R4，第 4–6 页]，没有验证上述修复率是稳定的调试能力量表。论文第 5 页的“473”在正文和表格中的统计单位表述不一致，不能把它宣传为本模型经过 473 名学习者效度检验。

## 5. H：首次评估前的提示覆盖

接口保留键名 `hint_dependency`，展示名称为“提示使用覆盖”。它是描述性指标，`direction = descriptive`；不称“依赖程度分数”，不以 `100 − H` 换算独立能力，不参加最低能力项、优势项或综合分排序。

令 \(Q_A\) 为至少有一次有效评估的唯一任务集合，\(hintFirst(q)\) 表示在该任务首次有效评估之前或该次评估中记录了提示使用：

\[
H = 100\times\frac{\sum_{q\in Q_A}hintFirst(q)}{|Q_A|}.
\]

没有已评估任务时 `H = null`。已有评估但没有平台提示记录时可显示 0%，文案必须限定为“未记录首次评估前提示”。任务首评之后的提示另列为后续提示使用任务数；只请求提示而没有有效评估的任务不进入该覆盖率的分子或分母。答案查看另外计数，不冒充提示。

可补充“提示后出现有效通过的请求比例”。其含义仅为时间顺序上的共现：同一次后续通过可能对应多次先前提示，任务难度和自我选择也未控制，故不能称为提示的因果效果或教学效率。

研究不支持一律惩罚求助。Aleven 等人的模型区分情境适当的求助、帮助回避和不恰当求助；任务熟悉度、知识状态和提示阅读行为都会改变解释 [R7，第 7–9、13、22 页]。该论文的 0.3/0.6 掌握阈值及 8 秒阅读阈值本身也说明依赖初始判断、需要经验验证 [R7，第 9 页]，不适合直接移植到中文 Spark 练习或生成式提示。

Choi 等人的研究比较了“提示”与“提示加反思”，发现反思设计与后续任务表现的改善相关，但两组提示数量没有显著差异 [R5，第 4–8 页]。因此本项目提供可选的完成后反思，例如“哪个检查排除了原来的假设”，不强制每次提示前填写长文，也不以字数或少点提示获得高分。

## 6. T：明确新场景中的首次表现

只有作者显式声明迁移关系的任务才是候选。目标任务须有不同于来源任务的 `Context`，与每个来源有知识点交集，且每个来源在目标首次有效评估之前的最近有效知识评估已通过；此处“之前”要求时间戳严格更早。仅仅进入下一课、换一道题或重做同题不算迁移。

目标任务的首次有效评估以前或同一时刻，平台不能已有同一目标场景的其他任务评估；否则已不满足当前模型的新场景条件。目标首评前或同一时刻查看其答案的任务也排除。不能通过先做目标、再补做来源、最后重做目标来倒填首次迁移证据。

令 \(Q_T\) 为满足上述条件的唯一目标任务集合，\(first(q)\) 为目标首次有效评估：

\[
T = 100\times\frac{\sum_{q\in Q_T}pass(first(q))}{|Q_T|}.
\]

没有合格目标时 `T = null`。缺少来源通过记录、来源元数据错误或新场景条件不满足都意味着证据不足，不能把这些候选计为迁移失败。提示辅助的首评通过正常计入，另列首评前未记录内置提示或答案查看的目标任务数量和通过率；题目重做可改善 K，但不能改写该目标的首次迁移结果。

研究依据是需要设计不同情境且保留相关问题结构的任务，而非仅按题目顺序命名迁移 [R1，第 19、31、40–41 页]；Choi 等人的后续任务也移除了提示与反思干预，以观察随后的应用表现 [R5，第 5、8 页]。本项目的场景标签及知识点交集仅是**作者定义且可审计的近迁移证据条件**，不能保证任务等难、排除所有表层线索，也不能证明广泛的远迁移能力。

## 7. 三道新增练习与证据连接

课程 `learning_spark` 的 `11_diagnosis_practice` 增加以下真实 Spark 练习。它们使用内置合成数据，无外部数据服务，基线为 PySpark 4.1.1 与独立安装的 Java 17 或以上受支持版本。

1. `debug_orders`：修复已给出的订单清洗及金额计算错误。检查无效数字、零/负边界、保留记录及逐行乘法结果。目标为调试修复与 `dataframe.filter`、`dataframe.with_column`。只有实际观察到失败到通过的过程才产生 D 证据，直接提交正确解不会凭题目标签得到调试满分。
2. `sensor_transfer`：把 `01_getting_started:15` 的 M&M 分类数量求和迁移到传感器上报条数场景。保留分组、求和、筛选和排序结构，明确“求和不等于统计行数”。来源场景与目标 `sensors` 不同，知识点共享 `dataframe.group_by`、`dataframe.aggregate`。
3. `weather_transfer`：把 `02_dataframes_schemas:14` 的博客显式 Schema 及布尔派生列迁移到天气观测。目标 `weather` 使用新的字段类型、数组列及两个业务阈值组合；知识点共享 `dataframe.schema`、`dataframe.with_column`。合成阈值仅是练习规则，不是气象预警标准。

每题提供完整函数契约、输入数据、输出字段、边界条件和可信测试。起始文件与参考答案的 `main` 检查一致，真实执行时使用课程可信检查验证学生函数。课程通过不代表该题已获测量效度验证；这些练习首先解决“系统是否有真正可执行的调试和迁移机会”。

## 8. 展示与推荐的工程规则

四项分别展示比例、样本单位及数量，不生成总能力分。K、D、T 的分母不同，最低比例只能作为当前练习排序的启发式，不能宣称它测出了学习者最弱的心理能力。H 始终排除于这种比较。

证据等级 `none / limited / available` 分别对应样本为 0、1–4、至少 5。5 的阈值仅是产品展示规则，不来自上述论文，不代表达到统计功效或测量信度。兼容字段 `confidence` 的 `none / limited / sufficient` 也只是同一展示枚举；界面和 API 使用说明不得称其为统计置信度。当前不输出伪精确的置信区间。

第二阶段工作台在每维附加 `evidence`，包含 `items`、`totalCount` 和展示上限 `limit`。样本从原评分循环同步生成：K 是各任务最近有效评估，D 是修复或未修复的失败过程，H 是各任务首评前的提示覆盖，T 是合格迁移任务的首次评估。展示最多 100 个计入样本，仅含任务标识、课程题目标题、结果和必要的辅助标记，不输出代码、聊天或原始错误正文。`totalCount` 对应该维分母，聚合仍使用完整合格历史；一个任务可以出现多个 D 过程，不能把 D 行数理解为题目数。这里增加的是可核查的解释，不是新的评分权重或测量模型。

工作台的课程完成率按目录中的逐课完成记录计算，与以上任务评估比率分开。读取工作台不会推进学习步骤或新增评估记录；课程范围筛选只限定目标课程，跨课程来源检查仍使用完整历史与目录。知识点详情沿用 K 的任务计数，一个任务可同时关联多个知识点，不应将各知识点计数相加当作总样本数。

推荐从真实课程目录选择一个尚未通过、符合当前深度且先修已具备的题目。优先匹配当前观察比例低于 100% 且有合格候选的非描述性维度，以及相关知识点。没有合格的新迁移机会时，可推荐巩固知识，而不能把已评估场景的重试称为一次新的迁移检验。

如果所有已测维度都为 100%，这些成功记录不意味着缺失维度也已掌握。已有评估或来源通过记录时，按迁移、调试、知识的顺序补充仍然缺失且具有合格候选的证据；迁移仍须满足来源、新场景等条件。完全没有学习历史时优先建立知识证据。已评估过的迁移题若尚未通过，可以作为知识巩固题推荐，推荐理由明确说明重做不会生成新的 T 证据。诊断文字与实际推荐方向一致，不把“尚缺证据”写成“能力不足”。

没有合格候选则返回空推荐与原因，不凭空生成题目、跳过先修或反复推荐已经通过的任务。推荐是可选择的形成性支持，不强制改变用户的学习路径。

Bartoš 的学习分析研究为低风险、可追溯且由教师掌控的支持设计提供了参考，同时明确正确性预测 AUC 不等于潜在掌握的构念效度 [R6，第 3、8–9 页]。其研究中调整后的主要后测差异不显著，且原始随机分配序列未完整保留 [R6，第 14–15 页]，不能据此宣称本系统已经证实提高学习成绩。

## 9. 验收与后续效度研究

工程验收至少覆盖：

- 空历史四项均为 `null`；只有平台提示但无评估不产生 H 分母；已有评估且无平台提示时 H 为 0%，不据此评价能力。
- 同一任务重复提交不重复增加 K、T 的任务分母；重复导入事件去重，冲突事件不贡献证据。同时间戳不按随机 ID 重排，提示和答案的同时间戳保守处理；课程筛选仍保留必要的跨课程来源顺序。
- 提示后通过正常改善 K、D；答案查看后的结果不新增知识/迁移证据，答案查看以前的合法证据仍可保留。
- 连续多个学习者失败构成一个未修复过程；真实评估通过才关闭；基础设施异常、AI 反馈或成功的语法检查不能冒充修复。
- 迁移必须具备来源、共享知识点、不同且尚未评估的目标场景及正确时间顺序；缺失来源记录、来源时间不严格更早、先做目标后做来源、答案泄露、相同场景都不得制造迁移成功。
- 推荐返回实际存在的练习及可解释理由；没有候选时允许为空；提示覆盖率不能决定最弱项。已测全为 100% 时优先补充合格的新迁移等缺失证据；同题重试只能称知识巩固，不能声称追加首次迁移证据。
- 三道新题均经过 YAML 加载、Python 编译、可信测试生成检查；Linux CI 用真实 Spark 执行参考答案及课程保留断言。只有这些检查实际通过，才报告相应工程验证完成。

效度验证是后续独立工作，不能用单元测试代替。小样本阶段先邀请教师检查知识点和任务契约，并通过学习者访谈/出声思考检验日志解释；使用人工标注的小样本核对学习者错误与环境错误的划分。再设计无答案泄露的新题与延迟任务，对比过程记录、结果及人工评分，报告缺失、退出、提示机会和外部帮助的局限 [R8，第 11–13 页]。

有足够数据后才考虑训练预测模型；切分应避免同一学习者跨训练/测试泄漏，并仅使用预测时点以前的数据。报告预测误差、校准及分组表现，也不能把预测准确度当作潜在能力效度 [R6，第 8–9 页]。不同任务的测量难度、学习机会和帮助条件需要单独研究，不能直接把简单任务比率升格为可比量表。

事件采集遵守最少必要原则：诊断优先使用题目标识、结果、错误类别、提示/答案时序等信息，而不是存储完整用户代码或完整 AI 对话。日志仅表示平台可见行为；数据清除、事件格式变化和课程改版会改变可解释范围，应向学习者说明。

## 10. 逐篇来源与版本说明

### R1：模型指导的调试教学与迁移

### R2：Deep Knowledge Tracing

Chris Piech、Jonathan Spencer、Jonathan Huang、Surya Ganguli、Mehran Sahami、Leonidas Guibas、Jascha Sohl-Dickstein（2015）。*Deep Knowledge Tracing*。此处引用所提供的 **arXiv:1506.05908v1**（2015-06-19）版本。[版本链接](https://arxiv.org/abs/1506.05908v1)，[DOI: 10.48550/arXiv.1506.05908](https://doi.org/10.48550/arXiv.1506.05908)。本地文件：`1506.05908v1.pdf`，13 页。

### R3：Programming Knowledge Tracing

### R5：提示与反思

Heeryung Choi、Jelena Jovanovic、Oleksandra Poquet、Christopher Brooks、Srećko Joksimović、Joseph Jay Williams（2023）。*The benefit of reflection prompts for encouraging learning with hints in an online programming course*。**The Internet and Higher Education, 58, 100903**。[DOI: 10.1016/j.iheduc.2023.100903](https://doi.org/10.1016/j.iheduc.2023.100903)。本地文件：`heeryung-the-internet-and-higher-education-hint-jovanovic.pdf`，10 页。
