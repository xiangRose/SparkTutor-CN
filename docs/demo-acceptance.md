# 第四阶段验收：可复现诊断演示

本阶段对应 Issue #7，将已有 Tracker、可信判题、四维诊断、推荐与历史复盘串成一条可以重复核查的演示流程。它验证系统行为，不是教学效果实验；技术报告和演示视频仍属后续阶段。

## 1. 先用无需 Spark 的模式验收

1. 在 VS Code 中打开 `sparktutor-vscode` 文件夹，确认 `sparktutor.pythonPath` 指向项目虚拟环境，按 F5 启动新的扩展开发宿主。
2. 执行“SparkTutor：打开诊断演示”，或从学习工作台的演示入口进入。
3. 选择“合成轨迹（无需 Spark）”与先失败再修复的场景，点击运行。打开页面和切换选项不会自动执行演示。
4. 完成后按阶段逐项查看四维画像、中文诊断、推荐、事件及前后复盘。

该模式只有执行结果是预设的；其余事件采集、评分、推荐导航与复盘使用实际代码。页面必须明确说明：这些是合成演示记录，未实际运行 Spark，不能作为自己的成绩或实验结果。

## 2. 核查任务 A 的错误、修改与求助

A 是 `learning_spark / 01_getting_started:15` 的 M&M 数量聚合。脚本精确打开单题，不为前序题目补造通过记录。

演示依次进行：

1. 仅按 State 分组，且把求和写成 count；运行失败。K、H、T 仍无证据，D 为 0/1。
2. 补上 Color 分组，记录编辑；编辑不会直接改善任何评分。
3. 再运行，count 仍只统计行数，未累计 Count 中的糖果数量。连续失败仍是一个未关闭的调试过程。
4. 请求实际课程 Hint。由于还没有首次有效提交，H 的分母仍为 0；提示本身不扣分。
5. 改为 sum 并提交，通过原课程检查。K=1/1、D=1/1、H=1/1；T 仍无证据。辅助修复可以计为调试成功。
6. 实际推荐器选择传感器新情境题 B，再使用原推荐导航打开它；推荐不匹配时停止演示，不硬改结果。

上述顺序中失败来自“运行”，不是首次“提交”。如果人工验收时先提交失败、再请求提示，H 首评前提示覆盖会不同，不能沿用这里的预期。

## 3. 核查两条迁移轨迹

B 是 `11_diagnosis_practice:sensor_transfer`，已声明 A 为来源。共享分组与聚合知识点，但输入从 CSV 变为显式 Schema 的元组，筛选改为站点参数，并增加并列排序、空输入与缺失站点约束。这是结构相近、约束增加的近迁移示例。

先失败再修复的场景：

- B 首次提交仍用 count，未通过：K=1/2、D=1/2、H=1/2、T=0/1。
- 编辑不会改变这些值。修复后提交通过：K=2/2、D=2/2、H=1/2，**T 仍为 0/1**。
- 回看 A 的通过阶段，其当时比例不能被 B 的失败倒灌。

另选首次通过场景，再次运行：

- 这是独立的新演示，不能解释为同一学习者重做后的新迁移机会。
- A 轨迹相同，B 首次提交通过后：K=2/2、D=1/1、H=1/2、T=1/1。
- B 未记录目标题的平台提示或答案，不代表证明了平台外完全独立学习。

H 的 100%→50% 来自新增一个无首评前提示的任务，不能解释成求助能力提高；这些预设轨迹也不能证明提示导致通过。

## 4. 真实 Spark 模式

选择“真实 Spark 课程测试”后运行同一场景。需要当前 Python 环境中的 PySpark 4.1.1、Java 17+ 及可用的 spark-submit；无需 AI 密钥、Docker 或远端服务。

- 运行预设错误和正确实现；正确提交必须经过原课程可信测试，不能只检查语法。
- 课程临时副本只调整为 local[2] 和 2 个 shuffle 分区，原断言保持一致，不修改仓库教材。
- 完成后明确显示真实 Spark 来源与核查结果。缺依赖、环境故障、超时或推荐变化时显示未完成，不能切换成合成结果冒充成功。
- 该模式可能耗时数分钟；运行时暂不操作普通学习，后端按顺序处理请求。关闭面板只关闭界面，不表示取消了 Spark 作业。

真实模式仍使用脚本预设代码，不是学生自主作答，不输出教学效果结论。

本次本机原生 Windows 验证中，A 的实际运行、修复提交与推荐跳转已通过，但 B 在创建本地数据的 Python worker 中发生 EOF/意外退出，完整真实轨迹未在该环境通过。没有把这类运行故障记成学习者失败或补造通过；真实流程以 Linux CI 的两条轨迹为验证基线。Windows 可先用合成模式验收页面，真实 Spark 演示建议在已准备的 Linux、WSL2 或 Dev Container 环境运行。

## 6. 终端与报告导出

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m sparktutor demo --scenario transfer_retry
.\.venv\Scripts\python.exe -X utf8 -m sparktutor demo --scenario transfer_first_pass --mode spark
```

使用 `--output <目录>` 指定报告位置，或 `--json` 在标准输出返回 JSON。每次在输出目录创建新子目录，不覆盖旧报告。目录包含 `report.json`（完整阶段证据）和 `summary.md`（中文摘要），都有演示与模式标记；不导出临时数据库和学生代码。
